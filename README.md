# Videoglue — склейка видео

Videoglue объединяет ролики в выбранном порядке: быстро копирует исходные потоки или перекодирует видео с обработкой изображения.

**Основные возможности:**

- Выбор одного или нескольких файлов и изменение порядка склейки.
- Вывод в MP4 или MKV: склейка без перекодирования либо сжатие в H.264/AAC.
- Удаление горизонтальных линий чересстрочного видео и стабилизация изображения.
- Обработка на NVIDIA или CPU с запросом разрешения перед переходом с GPU на CPU.
- Сохранение настроек и отображение хода обработки.
- Склейка разных разрешений и аудиоформатов, оценка размера результата и журнал диагностики.

## Запуск и добавление видео

На Windows запустите `dist/Videoglue.exe` — FFmpeg уже включён. Для запуска исходников установите Python 3.13+ с tkinter и зависимости (`python -m pip install -r requirements.txt`), положите `ffmpeg.exe` рядом с `main.py` и выполните `python main.py`. На Linux нужны tkinter, зависимости из `requirements.txt` и FFmpeg в `PATH`; запуск — `python3 main.py`.

В проект включена собственная статическая Windows x64-сборка **FFmpeg 7.1.5** из официального тега `n7.1.5`. Проверены CPU, NVENC, CUDA-деинтерлейсинг и OpenCL-стабилизация. Проверенные сборки Gyan 8.1.2 и 9.0.2 не используются: их `deshake_opencl` на тестовой NVIDIA завершался ошибкой `Cannot allocate memory`.

Нажмите **Добавить видео** и выберите один или несколько файлов (Ctrl или Shift для множественного выбора) либо перетащите их в таблицу: область приёма подсветится, а новые строки кратко выделятся цветом. Повторное добавление сохраняет текущие ролики и добавляет новые в конец. Все новые файлы отмечены галочками в первом столбце: снимите галочку, чтобы исключить файл из склейки, не убирая его из таблицы. Галочка в заголовке отмечает все файлы или снимает все отметки; если не выбран ни один пригодный файл, кнопка «Склеить» недоступна. Под таблицей отображается общий хронометраж отмеченных читаемых видео; он обновляется при изменении выбора и состава списка. При перестановке строк мышью захваченный файл появляется на приподнятой плашке под курсором, исходная строка приглушается, а соседние строки раздвигаются и показывают место вставки. Двойной клик по имени файла открывает ролик в системном видеоплеере. Красный значок-крестик в последней колонке подсвечивает строку при нажатии и после короткого перехода убирает файл из списка склейки, не удаляя его с диска. Формы значков основаны на [Bootstrap Icons](https://icons.getbootstrap.com/) (MIT). Поддерживаются `.mp4`, `.mov`, `.mkv`, `.avi`, `.webm`, `.m4v`. Повторы не добавляются, нечитаемые файлы пропускаются.

## Склейка и сжатие

Красный крестик в заголовке последней колонки очищает весь список, включая галочки и прочитанные метаданные. Файлы на диске сохраняются. Во время обработки очистка недоступна.

Выберите MP4 или MKV, нажмите **Склеить** и укажите результат. Кнопки **Открыть папку результата** и **Склеить** расположены под прогрессбарами справа. Имя итогового файла с расширением показывается под таблицей после примерного размера, в одной строке с хронометражем; кнопка открытия папки доступна после выбора пути. После успешной склейки папка откроется автоматически. По умолчанию **Сжать** включено; галочку можно снять для склейки через `-c copy` без фильтров, GPU и изменения качества. Исходные ролики должны быть совместимы по потокам, а контейнер — поддерживать их кодеки; например, для DV вместо MP4 выберите MKV или включите сжатие.

Над двумя панелями расположены галочки **Сжать** и **Использовать NVIDIA (NVENC)**. В левой панели «Настройки перекодирования» находятся формат, качество видео, частота кадров, качество аудио и разрешение; в правой «Фичи» — устранение горизонтальных линий, программный стабилизатор и две галочки обработки краёв. При включённом **Сжать** видео кодируется в H.264 за один проход с переменным битрейтом (VBR). Качество аудио: **Оригинал** (по умолчанию) или **AAC 128/192/256 кбит/с**. Совместимый оригинальный звук копируется без перекодирования; формат результата должен поддерживать его кодек. Исходники не изменяются; готовый результат сохраняется только после успешной обработки.

### Разные ролики в одном результате

При сжатии каждый исходник декодируется отдельно: можно объединять DV и H.264, разные размеры кадра и разные аудиоформаты. **Разрешение**: «Как у первого ролика» (первого отмеченного в порядке склейки), **1080p** или **720p**. Изображение вписывается с сохранением пропорций и учётом неквадратных пикселей; свободные области заполняются чёрным. При одинаковых размерах без изменения разрешения лишнее масштабирование не выполняется.

Если аудиопотоки различаются, например PCM в DV и AAC в MP4, выбранный «Оригинал» автоматически заменяется на **AAC 192 кбит/с** для этой операции; интерфейс сообщает об этом. Звук приводится к 48 кГц, стерео. Ролик без звука получает тишину, если в других роликах звук есть; полностью беззвучный список остаётся без аудиодорожки. Для несовместимых исходников склейка без сжатия предлагает включить «Сжать».

### Прогресс и примерный размер

При нескольких отмеченных файлах верхняя шкала показывает текущий ролик, нижняя — общий этап. При одном отмеченном файле отображается одна шкала. CPU-анализ стабилизации имеет свой этап: общий процент учитывает длительность роликов, затем при кодировании начинается заново. Кодирование показывает максимум 99% до успешного сохранения результата, после завершения — 100%.

Оценка размера расположена под таблицей в одной строке после общего хронометража. Она пересчитывается при смене галочек и настроек по уже прочитанным метаданным, без нового запуска FFmpeg. При сжатии учитываются адаптивный видеобитрейт, длительность, аудиорежим и небольшой запас на контейнер; без сжатия — сумма размеров выбранных файлов. До определения чересстрочности оценка предварительная и уточняется после анализа. Реальный размер может отличаться из-за VBR и особенностей контейнера.

### Адаптивный бюджет качества видео

| Режим | Доля исходного видеобитрейта | Предел, бит/пиксель/кадр |
|---|---:|---:|
| Максимальное (по умолчанию) | 90% | 0,30 |
| Высокое | 70% | 0,20 |
| Компактное | 45% | 0,14 |
| Малое | 25% | 0,10 |

Для каждого ролика выбирается меньшее из двух значений: `исходный видеобитрейт × доля` и `ширина × высота × выходной FPS × предел`. FPS учитывает удвоение при удалении чересстрочности и последующее снижение в режиме «Авто»; для переменной частоты используется объявленная средняя частота источника. При отсутствии размеров или FPS применяется только доля исходного битрейта. Бюджеты усредняются с весом по длительности каждого ролика. Пиковый VBR ограничен меньшим из 1,5 целевого битрейта и среднего исходного видеобитрейта.

Например, на «Малом» DV 720×576 с исходными 28,8 Мбит/с после удаления чересстрочности до 50 FPS получает около **2,07 Мбит/с**, а Full HD около 60 FPS с исходными 21,29 Мбит/с — **5,32 Мбит/с**. Расчёт одинаков для NVIDIA и CPU. Это ориентиры бюджета размера, а не гарантия одинакового визуального качества: движение, шум, звук и поведение однопроходного кодировщика влияют на итог. Оригинальный несжатый PCM-звук может занимать существенную долю файла; уменьшить её можно отдельным выбором AAC.

Настройка **Частота кадров**: «Оригинал» (по умолчанию) сохраняет исходные кадры и переменную частоту без дубликатов; «Авто» снижает 60 → 30, 59,94 → 29,97 и 50 → 25 кадров/с отдельно для каждого ролика. Частоты 30 и ниже остаются исходными. При невозможности определить FPS ролик также сохраняет исходную частоту. Снижение FPS экономит биты и может сделать движение менее плавным. Сохранённый числовой выбор старой версии заменяется на «Оригинал». Без «Сжать» настройка недоступна, исходная частота сохраняется.

## Удаление горизонтальных линий

Доступно при сжатии. **Авто** (по умолчанию) проверяет начало и середину каждого ролика и обрабатывает только обнаруженное чересстрочное видео. **Принудительно** обрабатывает все ролики, **Выключено** не удаляет линии. При включённой NVIDIA применяется `bwdif_cuda`, иначе — `bwdif` на CPU; анализ чересстрочности выполняется на CPU. Режим «Авто» может пропустить сложные случаи, а принудительная обработка прогрессивного видео — снизить резкость.

## Стабилизация

При сжатии доступны уровни **Слабый**, **Средний** и **Сильный**; по умолчанию стабилизатор выключен. Каждый ролик обрабатывается отдельно. NVIDIA использует `deshake_opencl` на видеокарте; CPU — двухпроходные `vidstabdetect` и `vidstabtransform` с отдельным индикатором анализа. Алгоритмы различаются, поэтому одинаковые уровни могут давать разный результат. В GPU-стабилизаторе отключена автоматическая обрезка, которая на длинных роликах могла приводить к чёрному изображению; на краях иногда видны отражённые участки кадра. Сильная стабилизация может ограничивать намеренное движение камеры, а на CPU — заметнее обрезать края.

## NVIDIA и переход на CPU

### Обработка краёв стабилизации

После программного стабилизатора расположены две галочки, по умолчанию выключенные; выбор сохраняется в `config.jsonc`.

- **Обрезать чёрную кромку** доступна при сжатии, в том числе без стабилизации. Python проверяет три кадра на 10%, 50% и 90% длительности, полученные готовым FFmpeg. Удаляются только почти сплошные тёмные края шириной не более 2,5% соответствующего размера и не более 16 пикселей. Широкие полосы и неуверенное определение оставляют кадр без обрезки. К найденной кромке добавляется один пиксель запаса против смешанной границы после сжатия. Обрезка выполняется после деинтерлейсинга, **до стабилизации**; небольшой равномерный масштаб восстанавливает исходный размер без растяжения пропорций. Та же обработка применяется при CPU-анализе движений. Галочка не отключает GPU-стабилизацию.
- **Убрать отражение стабилизации** доступна при сжатии и включённом стабилизаторе. Включает CPU-стабилизацию с чёрным заполнением свободных краёв (`crop=black`) и без автоматического увеличения (`optzoom=0`, `zoom=0`). Если выбрана NVIDIA, кодирование остаётся на NVENC; интерфейс показывает **«Стабилизация: CPU, кодирование: NVIDIA»**. Этот режим может быть медленнее, а при тряске чёрные края меняют форму и ширину.

Когда удаление отражения выключено, при выбранной NVIDIA сохраняется прежний GPU-стабилизатор. Обе галочки не применяются при склейке без сжатия. Проверка кромки отображается отдельным подготовительным этапом, найденные границы и фактический режим записываются в журнал. Для реализации используются готовый `ffmpeg.exe` и стандартная библиотека Python; FFprobe, новые зависимости и пересборка FFmpeg не требуются.

Галочка **Использовать NVIDIA (NVENC)** доступна при сжатии, если проверка видеокарты прошла успешно. Тогда кодирование (`h264_nvenc`), удаление линий (`bwdif_cuda`) и стабилизация (`deshake_opencl`) выполняются на GPU; при снятой галочке используются `libx264`, `bwdif` и `vidstab` на CPU. Для GPU-стабилизации нужен OpenCL в драйвере NVIDIA. Декодирование, проверка чересстрочности, объединение потоков и передача кадров между CUDA и OpenCL всё ещё могут задействовать CPU.

Если GPU-обработка не удалась, программа спросит: **«Продолжить обработку на CPU?»** Ответ **Да** повторит обработку на CPU, **Нет** отменит операцию без неполного результата. Фактический способ обработки указывается после завершения.

## Журнал диагностики

Окна ошибок показывают понятное описание и путь к **Videoglue.log** рядом с EXE (при запуске исходников — рядом с `debug_log.py`). Журнал содержит настройки, пути исходников, версию FFmpeg, полные команды, вывод ошибок, коды завершения, исключения и решение о переходе на CPU. Размер одного журнала ограничен 5 МиБ, сохраняются три резервных файла. Если записать журнал не удалось, обработка продолжается, а сообщение об ошибке сообщает о недоступности журнала. После успешного CPU-повтора техническая ошибка GPU остаётся в журнале.

## Настройки и разработка

Выборы сохраняются в `config.jsonc` рядом с EXE (для исходников — рядом с `settings.py`); файл поддерживает комментарии и конечные запятые, но при автосохранении комментарии переписываются. При первом запуске новой версии сжатие включится и для существующих конфигураций; после этого пользователь может выключить его, и выбор будет запоминаться. Последние папки подставляются в диалоги, список роликов при запуске остаётся пустым.

Длительность, FPS и битрейт читаются одним запуском FFmpeg. Метаданные неизменённых файлов повторно используются в ограниченном кэше; изменение размера или временных меток вызывает повторное чтение. Закрытие окна прерывает также подготовительные проверки, а тайм-аут подготовки выводится как ошибка и возвращает доступность интерфейса. Значки таблицы переиспользуются только для видимых строк. В многовходных графах число потоков декодирования и фильтрации ограничено, чтобы снизить расход памяти при обработке длинных списков.

Проверка: `py -3.14 -m unittest -v test_main`.

### Сборка в EXE на Windows

Собирайте приложение на Windows с установленным **Python 3.14** и компонентом **Tcl/Tk (tkinter)**. Все команды ниже выполняются в PowerShell из корня проекта, где находятся `main.py` и `Videoglue.spec`.

1. Убедитесь, что в корне проекта есть рабочий `ffmpeg.exe`: он будет включён внутрь приложения. Для собственной сборки FFmpeg см. раздел «Кастомная сборка FFmpeg» ниже.
2. Создайте виртуальное окружение и установите зависимости и PyInstaller:

   ```powershell
   py -3.14 -m venv .venv
   .\.venv\Scripts\python.exe -m pip install --upgrade pip
   .\.venv\Scripts\python.exe -m pip install -r requirements.txt pyinstaller
   ```

3. Соберите приложение с помощью готового spec-файла:

   ```powershell
   .\.venv\Scripts\python.exe -m PyInstaller --noconfirm --clean Videoglue.spec
   ```

   `Videoglue.spec` задаёт сборку в один EXE без консольного окна, включает `ffmpeg.exe` и использует локальный `hook-tkinterdnd2.py` для поддержки перетаскивания файлов. Параметр `--clean` очищает кэш сборки, а `--noconfirm` разрешает перезапись предыдущего результата.

4. Готовый файл — **`dist\Videoglue.exe`**. Запустите его для проверки:

```powershell
.\dist\Videoglue.exe
```

Для переноса приложения на другой компьютер достаточно `Videoglue.exe`: отдельно устанавливать Python и копировать FFmpeg не нужно. Для GPU-обработки на целевом компьютере нужен подходящий драйвер NVIDIA с CUDA/OpenCL. Настройки `config.jsonc` и журнал `Videoglue.log` создаются рядом с EXE, поэтому размещайте его в папке, доступной для записи.

После изменения исходников или замены `ffmpeg.exe` повторите команду сборки из шага 3. Промежуточные файлы находятся в `build/`, результат — в `dist/`; обе папки исключены из Git через `.gitignore`.

### Публикация релиза в GitVerse

Готовые версии приложения публикуются в **релизах GitVerse** как ZIP-архивы, прикреплённые к релизу (ассеты). Папка `dist/` остаётся в `.gitignore`: для загрузки вложения релиза добавлять EXE или архив в Git не требуется. ZIP входит в список допустимых форматов вложений GitVerse.

1. Выберите номер версии, например `1.0.0`, и загрузите в репозиторий исходники, из которых будет собрана эта версия.
2. Выполните тесты в окружении сборки:

   ```powershell
   .\.venv\Scripts\python.exe -m unittest -v test_main
   ```

   Учитывайте пропуски аппаратных тестов: они не подтверждают работу GPU (подробнее в разделе «Тесты»).
3. Соберите EXE по инструкции выше и проверьте запуск `dist\Videoglue.exe`.
4. Создайте архив, заменив номер версии на актуальный:

   ```powershell
   Compress-Archive -LiteralPath ".\dist\Videoglue.exe" -DestinationPath ".\dist\Videoglue-1.0.0-windows-x64.zip" -Force
   ```

5. Откройте репозиторий на GitVerse → **«Релизы»** и создайте релиз:
   - тег версии — `v1.0.0`, привязанный к коммиту, из которого собран EXE;
   - название — `Videoglue 1.0.0`;
   - описание — изменения этой версии и инструкция запуска.
6. Прикрепите `dist\Videoglue-1.0.0-windows-x64.zip` как ассет, дождитесь загрузки и опубликуйте релиз.
7. Проверьте, что архив доступен для скачивания, и сохраните ссылку на опубликованный релиз.

Пример описания релиза:

```text
Videoglue 1.0.0 — приложение для склейки видео на Windows x64.

Скачайте Videoglue-1.0.0-windows-x64.zip, распакуйте в доступную
для записи папку и запустите Videoglue.exe.
Python устанавливать не нужно, FFmpeg включён.
```

### Тесты

В `test_main.py` — 34 теста. Они проверяют порядок и выбор файлов, очистку списка, сохранение настроек, копирование аудио/видео, FPS и число кадров, бюджет битрейта и оценку размера, прогресс, смешанную склейку DV/H.264/беззвучного ролика в разных разрешениях, CPU/GPU-фильтры, согласие на переход на CPU, тайм-ауты, освобождение процессов и устойчивость журнала к ошибкам записи. Отдельные тесты проверяют видеобитрейт и временные метки VFR при NVENC, распознавание узкой кромки без удаления широких полос и режим CPU-стабилизации с NVENC. Проверки оформления не привязаны к точному числу элементов значков или длительности анимации.

GUI-тестам нужен графический рабочий стол. Интеграционные тесты используют проектный FFmpeg; части проверок нужен внешний `ffprobe` в `PATH` (в приложение он не включается). Аппаратные тесты пропускаются без доступного NVENC. Успешный прогон с пропусками не подтверждает работу GPU. Длительный прогон стабилизатора на реальном ролике проверяется отдельно: короткие тесты контролируют совместимость и число кадров, но не гарантируют отсутствие деградации спустя десятки минут.

## Кастомная сборка FFmpeg

`build_ffmpeg.sh` собирает Windows x64 EXE из исходников в Ubuntu/WSL с помощью MinGW. Внешние библиотеки связаны статически; рядом с программой не нужны DLL FFmpeg, x264 или vidstab. Для ускорения распаковки однофайлового приложения удалены неиспользуемые внешние библиотеки, сетевые протоколы, устройства захвата, кодировщики и фильтры. Само по себе это не гарантирует ускорения кодирования.

**Состав:** FFmpeg 7.1.5, x264 (ревизия `b35605ace3ddf7c1a5d67a2eb553f034aef41d55`), vid.stab 1.1.1, nv-codec-headers 12.2.72.0, OpenCL Headers и статический ICD Loader 2024.10.24. Сохранены встроенные декодеры и демультиплексоры FFmpeg, чтение локальных файлов, H.264 на CPU/NVENC, AAC, копирование потоков, MP4/MKV и фильтры проекта, включая `bwdif_cuda`, `deshake_opencl` и двухпроходный vidstab. FFprobe и проигрыватель в комплект не входят. Внешних декодеров вроде dav1d нет: входной AV1 этой сборкой не поддерживается. Драйвер NVIDIA с CUDA/OpenCL по-прежнему нужен для GPU-обработки; CPU-режим не требует OpenCL.dll.

Установка инструментов в Ubuntu/WSL:

```bash
sudo apt-get update
sudo apt-get install -y git build-essential gcc-mingw-w64-x86-64 g++-mingw-w64-x86-64 nasm cmake clang llvm pkg-config
bash /mnt/d/ARCHIV/MULTIMEDIA/Videoglue/build_ffmpeg.sh
```

По умолчанию исходники и результаты находятся в `~/videoglue-ffmpeg-build`, вне проекта. Другой рабочий каталог можно передать первым аргументом, число потоков — через `JOBS=4`. Результат: `output/ffmpeg.exe`; `output/sources.txt` содержит ревизии зависимостей и SHA-256 бинарника. Скрипт использует GPL-компоненты x264 и vidstab: сборка FFmpeg распространяется по GPL, исходники и параметры сборки следует сохранять вместе с распространяемой версией.

Скрипт применяет локальный патч `ffmpeg-nvenc-rate.patch`: он добавляет параметр NVENC `rc_framerate` только для расчёта битрейта. После объединения VFR-роликов FFmpeg мог передавать NVENC резервную частоту 30 кадров/с вместо фактических около 60, из-за чего результат получался примерно вдвое больше бюджета. Программа передаёт среднюю выходную частоту с учётом длительности роликов, удаления чересстрочности и режима «Авто». Патч не меняет временные метки, число кадров или режим синхронизации. Его контрольная сумма записывается в `sources.txt`. Внешний FFmpeg без этого параметра остаётся совместимым, но данное исправление расчёта NVENC в нём не применяется.

Перед заменой рабочего бинарника проверьте новую сборку тестами. После копирования её в корень проекта пересоберите приложение с очисткой, чтобы PyInstaller точно включил обновлённый файл:

```powershell
py -3.14 -m unittest -v test_main
py -3.14 -m PyInstaller --noconfirm --clean Videoglue.spec
```

Для смешанной склейки в набор фильтров добавлены `pad`, `anullsrc`, `atrim` и `apad`. Обновлённая сборка прошла все 33 теста, включая реальные CPU/GPU-операции. Первоначальное сокращение набора компонентов уменьшило FFmpeg со 131,66 до примерно **19 МиБ**, а однофайловое приложение — с 61,72 до примерно **20 МиБ**. SHA-256 текущего `ffmpeg.exe`: `3fd1684d272456b080318ff919b00841627dc66653aab8b23b53560ce3c632f3`.
