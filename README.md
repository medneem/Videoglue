# Videoglue — склейка видео

[![Windows build](https://github.com/medneem/Videoglue/actions/workflows/build-windows.yml/badge.svg)](https://github.com/medneem/Videoglue/actions/workflows/build-windows.yml)
[![Latest release](https://img.shields.io/github/v/release/medneem/Videoglue?label=release)](https://github.com/medneem/Videoglue/releases/latest)

Бесплатное приложение с русским интерфейсом: объединяет видео в выбранном порядке, сжимает его и при необходимости устраняет чересстрочность и дрожание камеры. Обработка выполняется локально на компьютере — на CPU или видеокарте NVIDIA.

**Репозиторий:** [GitHub / medneem / Videoglue](https://github.com/medneem/Videoglue) · **Лицензия собственного кода:** [MIT](LICENSE)

## Возможности

- Добавление видео через диалог или перетаскиванием в окно, выбор галочками и изменение порядка мышью.
- Сохранение в **MP4** или **MKV**: быстрое копирование потоков либо перекодирование в **H.264**.
- Сохранение совместимого оригинального звука или сжатие в **AAC**.
- Объединение видео с разными разрешениями, кодеками и аудиоформатами при включённом сжатии.
- Удаление горизонтальных линий чересстрочного видео, стабилизация и обработка краёв.
- Кодирование на NVIDIA NVENC или CPU; переход с GPU на CPU только после подтверждения.
- Общий хронометраж, примерный размер результата, прогресс и журнал диагностики.

**Входные расширения:** `.mp4`, `.mov`, `.mkv`, `.avi`, `.webm`, `.m4v`. Возможность обработки зависит от кодека внутри файла, а не только от расширения.

## Быстрый старт

### Windows: готовое приложение

1. Скачайте ZIP по ссылке [GitHub Releases](https://github.com/medneem/Videoglue/releases/latest) (`Videoglue-v0.1.N-windows-x64.zip`).
2. Распакуйте в **новую папку**, запустите `Videoglue.exe`.

Python не требуется. Файлы `ffmpeg.exe` и `ffprobe.exe` находятся рядом с приложением. Папки `_internal` нет. Приложение может работать на CPU без NVIDIA. Для GPU-обработки нужна видеокарта NVIDIA с подходящим драйвером и поддержкой CUDA/OpenCL.

Если готового релиза ещё нет, используйте [исходники](#запуск-из-исходников) или [соберите EXE](#сборка-exe). После локальной сборки он находится в `dist\Videoglue.exe`.

### Linux

Запускайте приложение из исходников. Нужны Python 3.13+, tkinter, зависимости проекта и FFmpeg в `PATH`. Подробности — в разделе [«Запуск из исходников»](#запуск-из-исходников).

## Как склеить видео

1. Нажмите **«Добавить видео»** или перетащите файлы в таблицу. Для множественного выбора используйте Ctrl или Shift.
2. Расставьте ролики в нужном порядке, перетаскивая строки мышью.
3. Оставьте галочки у файлов, которые должны попасть в результат.
4. Выберите **MP4** или **MKV**, настройте сжатие и обработку изображения.
5. Нажмите **«Склеить»**, укажите путь результата и дождитесь завершения.

Исходные файлы не изменяются. Готовый результат сохраняется только после успешной обработки, затем его папка открывается автоматически.

### Управление списком

| Действие | Результат |
|---|---|
| Повторное добавление файлов | Новые ролики добавляются в конец; повторы не добавляются, нечитаемые файлы пропускаются |
| Галочка в строке | Включает или исключает ролик из склейки, оставляя его в списке |
| Галочка в заголовке | Выбирает все ролики или снимает все отметки |
| Двойной клик по имени | Открывает видео в системном проигрывателе |
| Красный крестик в строке | Убирает ролик из списка, не удаляя файл с диска |
| Красный крестик в заголовке | Очищает весь список; во время обработки недоступен |

В колонке **«Размер, МиБ»** показан размер каждого исходного файла с одним знаком после запятой (1 МиБ = 1 048 576 байт); если размер недоступен, отображается «—».

Под таблицей показаны хронометраж выбранных роликов, примерный размер и имя результата. Кнопка **«Открыть папку результата»** доступна после выбора пути. Если не выбран ни один пригодный файл, склейка недоступна.

### Сжатие или быстрое копирование

| Режим | Когда использовать | Особенности |
|---|---|---|
| **«Сжать» включено** — по умолчанию | Нужно уменьшить размер, объединить разные ролики или обработать изображение | Видео перекодируется в H.264; доступны настройки качества, фильтры и NVIDIA |
| **«Сжать» выключено** | Нужно быстро объединить совместимые ролики без перекодирования | Потоки копируются через `-c copy`; качество и исходная частота кадров сохраняются, фильтры не применяются |

При копировании исходники должны быть совместимы по потокам, а контейнер результата — поддерживать их кодеки. Например, для DV выберите MKV или включите сжатие. Если ролики несовместимы для копирования, приложение предложит включить **«Сжать»**.

## Настройки качества

Настройки перекодирования доступны при включённом **«Сжать»**.

| Параметр | Варианты и поведение |
|---|---|
| **Качество видео** | Максимальное (по умолчанию), Высокое, Компактное, Малое; более компактные режимы уменьшают бюджет видеобитрейта |
| **Частота кадров** | Оригинал (по умолчанию) сохраняет исходные кадры и переменную частоту; Авто снижает 60 → 30, 59,94 → 29,97 и 50 → 25 кадров/с |
| **Качество аудио** | Оригинал (по умолчанию) или AAC 128/192/256 кбит/с |
| **Разрешение** | Как у первого отмеченного ролика (по умолчанию), 1080p или 720p |

Частоты 30 кадров/с и ниже в режиме **«Авто»** остаются исходными. Если FPS определить не удалось, частота также не меняется. Снижение FPS экономит место, но может сделать движение менее плавным.

### Ролики с разными параметрами

При сжатии каждый исходник декодируется отдельно. Изображение вписывается в выбранное разрешение с сохранением пропорций и учётом неквадратных пикселей; свободные области заполняются чёрным. Без необходимости лишнее масштабирование не выполняется.

Если аудиопотоки несовместимы, например PCM в DV и AAC в MP4, режим **«Оригинал»** автоматически заменяется на **AAC 192 кбит/с** для этой операции. Интерфейс сообщает о замене; звук приводится к 48 кГц, стерео. Ролику без звука добавляется тишина, если звук есть в других роликах. Полностью беззвучный список остаётся без аудиодорожки.

### Прогресс и размер файла

- Для нескольких роликов верхняя шкала показывает текущий ролик, нижняя — общий этап. Для одного ролика используется одна шкала.
- CPU-анализ стабилизации отображается отдельным этапом; при переходе к кодированию процент начинается заново.
- Кодирование показывает не более 99% до успешного сохранения результата; после завершения — 100%.
- Размер пересчитывается по уже прочитанным метаданным при изменении выбора или настроек. Без сжатия это сумма размеров выбранных файлов; со сжатием — оценка по видеобитрейту, звуку и длительности.

Оценка размера предварительная: анализ чересстрочности может её уточнить, а переменный битрейт (VBR) и особенности контейнера влияют на итог.

<details>
<summary>Как рассчитывается бюджет качества видео</summary>

Видео кодируется за один проход с переменным битрейтом. Бюджет зависит от исходного видеобитрейта, размеров кадра и выходного FPS.

| Качество | Доля исходного видеобитрейта | Предел, бит/пиксель/кадр |
|---|---:|---:|
| Максимальное | 90% | 0,30 |
| Высокое | 70% | 0,20 |
| Компактное | 45% | 0,14 |
| Малое | 25% | 0,10 |

Для каждого ролика выбирается меньшее из значений:

```text
исходный видеобитрейт × доля
ширина × высота × выходной FPS × предел
```

FPS учитывает удвоение при удалении чересстрочности и последующее снижение в режиме «Авто». Для переменной частоты используется объявленная средняя частота источника. При отсутствии размеров или FPS применяется только доля исходного битрейта.

Бюджеты роликов усредняются с весом по длительности. Пиковый VBR ограничен меньшим из 1,5 целевого битрейта и среднего исходного видеобитрейта. Расчёт одинаков для CPU и NVIDIA.

Например, на «Малом» DV 720×576 с исходными 28,8 Мбит/с после удаления чересстрочности до 50 FPS получает около 2,07 Мбит/с, а Full HD около 60 FPS с исходными 21,29 Мбит/с — около 5,32 Мбит/с.

Это ориентир размера, а не гарантия одинакового визуального качества. Движение, шум и звук влияют на результат; оригинальный PCM-звук может занимать существенную долю файла.

## Обработка изображения

Все функции этого раздела работают только при включённом сжатии.

### Удаление горизонтальных линий

Деинтерлейсинг устраняет «гребёнку» на чересстрочном видео.

- **Авто** — по умолчанию: проверяет начало и середину каждого ролика и обрабатывает обнаруженное чересстрочное видео.
- **Принудительно** — обрабатывает все ролики.
- **Выключено** — оставляет изображение без деинтерлейсинга.

На NVIDIA используется `bwdif_cuda`, на CPU — `bwdif`; анализ выполняется на CPU. Автоматическое определение может пропустить сложные случаи, а принудительная обработка прогрессивного видео — снизить резкость.

### Стабилизация

По умолчанию выключена. Доступны уровни **Слабый**, **Средний** и **Сильный**; каждый ролик обрабатывается отдельно.

- **NVIDIA:** `deshake_opencl` на GPU. Автоматическая обрезка отключена, поэтому у краёв иногда видны отражённые участки изображения.
- **CPU:** двухпроходная обработка `vidstabdetect` и `vidstabtransform` с отдельным этапом анализа.

Алгоритмы различаются: одинаковый уровень не гарантирует одинаковый результат. Сильная стабилизация может ограничивать намеренное движение камеры, а на CPU — заметнее обрезать края.

### Обработка краёв

Обе опции по умолчанию выключены.

| Опция | Что делает |
|---|---|
| **Обрезать чёрную кромку** | Находит узкие почти сплошные тёмные края и удаляет их перед стабилизацией. Работает и без стабилизатора; широкие полосы не удаляет |
| **Убрать отражение стабилизации** | Переводит стабилизацию на CPU с чёрным заполнением свободных краёв без автоматического увеличения. При выбранной NVIDIA кодирование остаётся на NVENC |

Проверка кромки анализирует кадры на 10%, 50% и 90% длительности. Удаляются края шириной не более 2,5% размера и не более 16 пикселей с одним пикселем запаса. При неуверенном определении обрезка не применяется. Небольшой равномерный масштаб восстанавливает размер без растяжения пропорций; обработка выполняется после деинтерлейсинга и до стабилизации, включая CPU-анализ движения.

Удаление отражения доступно только с включённым стабилизатором и использует `crop=black`, `optzoom=0`, `zoom=0`. Интерфейс показывает **«Стабилизация: CPU, кодирование: NVIDIA»**, если кодирование осталось на GPU. Этот режим может быть медленнее, а чёрные края при тряске — менять форму и ширину.

## NVIDIA и CPU

Галочка **«Использовать NVIDIA (NVENC)»** становится доступна при включённом сжатии после успешной проверки видеокарты.

| Операция | NVIDIA | CPU |
|---|---|---|
| Кодирование H.264 | `h264_nvenc` | `libx264` |
| Деинтерлейсинг | `bwdif_cuda` | `bwdif` |
| Стабилизация | `deshake_opencl` | `vidstabdetect` + `vidstabtransform` |

GPU-стабилизации нужен OpenCL в драйвере NVIDIA. Декодирование, анализ чересстрочности, объединение потоков и передача кадров между CUDA и OpenCL могут задействовать CPU даже при выбранной NVIDIA.

Если GPU-обработка не удалась, приложение спросит **«Продолжить обработку на CPU?»**:

- **Да** — повторить обработку на CPU.
- **Нет** — отменить операцию без неполного результата.

Фактический режим показывается после завершения. При выключенном сжатии GPU и фильтры не используются.

## Настройки и диагностика

| Файл | Назначение |
|---|---|
| `config.jsonc` | Настройки обработки, положение и размер окна, последние папки |
| `Videoglue.log` | Настройки операции, пути исходников, версия и команды FFmpeg, ошибки и переходы на CPU |

В готовом приложении эти файлы находятся рядом с EXE, при запуске исходников — в корне проекта. Список роликов при запуске остаётся пустым. Настройки поддерживают комментарии и конечные запятые, но автосохранение переписывает комментарии.

Журнал ограничен 5 МиБ на файл; сохраняются три резервные копии. Окно ошибки показывает описание и путь к журналу. После успешного повтора на CPU исходная ошибка GPU остаётся в журнале. Если запись журнала недоступна, обработка продолжается.

При диагностике сначала проверьте журнал, кодеки исходников и доступность драйвера NVIDIA. Проектная сборка FFmpeg **не поддерживает входной AV1**: внешний декодер вроде dav1d в неё не включён. Для склейки без сжатия проверьте совместимость потоков и контейнера.

## Запуск из исходников

### Windows

Установите Python 3.14 с компонентом **Tcl/Tk (tkinter)**. Выполняйте команды PowerShell из корня проекта:

```powershell
py -3.14 -m venv .venv
.\.venv\Scripts\python.exe -m pip install --upgrade pip
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe main.py
```

Рядом с `main.py` должен находиться проектный `ffmpeg.exe`. Активировать виртуальное окружение не обязательно: команды вызывают его Python напрямую.

### Linux

Установите Python 3.13+, tkinter, поддержку `venv` и FFmpeg средствами своего дистрибутива. Затем из корня проекта выполните:

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python main.py
```

FFmpeg должен быть доступен в `PATH`. Для CPU-стабилизации ему нужны фильтры vid.stab; для GPU-функций — соответствующие фильтры и кодировщик NVIDIA.

## Тестирование

В `test_main.py` находятся **35 тестов**; новые тесты портативной версии — в `test_release.py`. Из подготовленного Windows-окружения:

```powershell
.\.venv\Scripts\python.exe -m unittest -v test_main
```

Проверки охватывают список роликов и настройки, совместимость потоков, смешанные исходники и звук, FPS и временные метки, бюджет битрейта, прогресс, CPU/GPU-фильтры, обрезку кромки, согласие на переход на CPU, тайм-ауты и освобождение процессов.

- GUI-тестам нужен графический рабочий стол.
- Интеграционные тесты используют проектный FFmpeg; части проверок нужен `ffprobe` в `PATH` (в Windows ZIP он включён отдельным файлом).
- Аппаратные проверки пропускаются без доступного NVENC. Успешный прогон с пропусками не подтверждает работу GPU.
- Длительную стабилизацию реального видео проверяют отдельно: короткие тесты не гарантируют отсутствие деградации спустя десятки минут.

## Сборка EXE

Для Windows используется PyInstaller `--onefile` и Python 3.13+:

```powershell
py -3.13 -m pip install -r requirements.txt pyinstaller
py -3.13 -m PyInstaller --noconfirm --clean Videoglue.spec
```

Результат — `dist\Videoglue.exe`, без `_internal`. `ffmpeg.exe` и `ffprobe.exe` не встроены в EXE: скопируйте их рядом с программой. Для локального запуска из исходников FFmpeg должен быть доступен рядом с кодом или в `PATH`.

## GitHub Actions и релизы

[Windows pipeline](https://github.com/medneem/Videoglue/actions/workflows/build-windows.yml) запускается при push в `master`, pull request и вручную.
Номер релиза: `0.1.<github.run_number>` (например, `0.1.42`); Git-тег — `v0.1.42`; архив — `Videoglue-v0.1.42-windows-x64.zip`. Базовая версия `BASE_VERSION` задаётся в workflow. Номер версии отображается в заголовке программы, ресурсах Windows EXE и `VERSION.txt`.

CI устанавливает Python, запускает тесты, загружает **Gyan FFmpeg Full x64** (нужен OpenCL), проверяет SHA-256 и доступность фильтров, собирает EXE и плоский ZIP. Архив проверяется на наличие обязательных файлов и отсутствие `_internal`.

Состав архива:

```text
Videoglue.exe
ffmpeg.exe
ffprobe.exe
VERSION.txt
FFMPEG_VERSION.txt
LICENSE
LICENSE_FFMPEG.txt
THIRD_PARTY_NOTICES.md
```

После успешного запуска на `master` ZIP публикуется в **Actions → Artifacts** (14 дней) и в **GitHub Releases**. В pull request создаётся только артефакт, без релиза. Повторный запуск использует тот же номер версии.

**Примечание о совместимости:** для Gyan FFmpeg 8.1.2 и 9.0.2 ранее наблюдались ошибки OpenCL-стабилизации на NVIDIA. CI проверяет наличие фильтров, но не может проверить GPU-обработку на Windows runner. При необходимости можно заменить внешний `ffmpeg.exe` проверенной собственной сборкой без пересборки Videoglue.

## FFmpeg и совместимость

Исторически проект использовал собственную Windows x64-сборку **FFmpeg 7.1.5** из тега `n7.1.5`. Новый GitHub CI использует Gyan Full. Ниже оставлены сведения о прежней сборке. Она включает CPU-кодирование, NVENC, CUDA-деинтерлейсинг и OpenCL-стабилизацию. Рядом с приложением не нужны DLL FFmpeg, x264 или vid.stab; для GPU по-прежнему нужен драйвер NVIDIA.

Исторический `build_ffmpeg.sh` собирал бинарник из Ubuntu/WSL с помощью MinGW. В текущем GitHub-репозитории этого скрипта нет; следующие команды требуют получить его из прежних исходников. Установите инструменты и запустите скрипт, подставив свой путь к проекту:

```bash
sudo apt-get update
sudo apt-get install -y git build-essential gcc-mingw-w64-x86-64 g++-mingw-w64-x86-64 nasm cmake clang llvm pkg-config
bash /mnt/d/ARCHIV/MULTIMEDIA/Videoglue/build_ffmpeg.sh
```

По умолчанию рабочий каталог — `~/videoglue-ffmpeg-build`, число потоков — 8. Другой каталог задаётся первым аргументом, число потоков — переменной `JOBS`.

- `output/ffmpeg.exe` — готовый бинарник.
- `output/sources.txt` — ревизии зависимостей и SHA-256 бинарника и патча.

После собственной сборки замените `ffmpeg.exe` рядом с `Videoglue.exe` и запустите тесты: пересборка приложения не требуется.

<details>
<summary>Состав, ограничения и патч NVENC</summary>

| Компонент | Версия / ревизия |
|---|---|
| FFmpeg | 7.1.5 (`n7.1.5`) |
| x264 | `b35605ace3ddf7c1a5d67a2eb553f034aef41d55` |
| vid.stab | 1.1.1 |
| nv-codec-headers | 12.2.72.0 |
| OpenCL Headers и статический ICD Loader | 2024.10.24 |

В сборке оставлены чтение локальных файлов, встроенные декодеры и демультиплексоры, H.264 на CPU/NVENC, AAC, копирование потоков, MP4/MKV и фильтры приложения. Удалены неиспользуемые внешние библиотеки, сетевые протоколы, устройства захвата, кодировщики и фильтры. FFprobe и проигрыватель не включены; входной AV1 не поддерживается. CPU-режим не требует OpenCL.dll.

Сборки Gyan 8.1.2 и 9.0.2 не используются: на тестовой NVIDIA их `deshake_opencl` завершался ошибкой `Cannot allocate memory`. В проектной GPU-стабилизации отключена автоматическая обрезка, которая на длинных роликах могла приводить к чёрному изображению.

Локальный `ffmpeg-nvenc-rate.patch` добавляет параметр NVENC `rc_framerate` для расчёта битрейта. После объединения VFR-роликов FFmpeg мог передавать резервные 30 кадров/с вместо фактических около 60, увеличивая размер примерно вдвое относительно бюджета. Приложение передаёт среднюю выходную частоту с учётом длительности, деинтерлейсинга и режима «Авто».

Патч не меняет временные метки, число кадров или синхронизацию. Внешний FFmpeg без этого параметра остаётся совместимым, но исправление расчёта NVENC в нём не применяется.

## Структура проекта

| Файл | Назначение |
|---|---|
| `main.py` | Точка входа |
| `window.py` | Главное окно, настройки и события фоновых задач |
| `video_list.py` | Таблица роликов, выбор, перетаскивание и значки |
| `merge.py` | Склейка, кодирование, фильтры и оценка размера |
| `ffmpeg.py` | Поиск FFmpeg, метаданные и проверка NVENC |
| `black_border.py` | Анализ узкой чёрной кромки |
| `settings.py` | Чтение и сохранение JSONC-настроек |
| `debug_log.py` | Журнал диагностики |
| `test_main.py` | Автоматические тесты |
| `benchmark_stabilization.py` | Отдельная проверка производительности стабилизации |
| `Videoglue.spec`, `hook-tkinterdnd2.py` | Настройки упаковки EXE |
| `build_ffmpeg.sh`, `ffmpeg-nvenc-rate.patch` | Исторические инструменты собственной FFmpeg-сборки (отсутствуют в текущем GitHub-репозитории) |
| `.github/workflows/build-windows.yml` | GitHub Actions, ZIP, Releases |
| `version.py`, `scripts/stamp_version.py` | Версионирование |
| `test_release.py` | Тесты версии и пути FFmpeg |
| `THIRD_PARTY_NOTICES.md` | Сторонние лицензии |
| `requirements.txt` | Python-зависимости приложения |

Метаданные неизменённых файлов кэшируются; изменение размера или временных меток вызывает повторное чтение. Фоновые задачи не обновляют tkinter напрямую: события передаются главному потоку через очередь. Закрытие окна прерывает обработку и подготовительные проверки; число потоков декодирования и фильтрации ограничено для снижения расхода памяти.
